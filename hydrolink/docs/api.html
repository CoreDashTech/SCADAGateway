REST API · CoreDash HydroLink

API สำหรับเชื่อมต่อข้อมูล SCADA เข้ากับระบบอื่นขององค์กร (ERP, BI, BMS) ใช้มาตรฐาน REST และข้อมูล JSON ไม่ผูกขาดกับผู้พัฒนา

Base URLhttps://scada.hydrolink.example (กำหนดจริงเมื่อส่งมอบ)
เวอร์ชันv1 — เส้นทางขึ้นต้นด้วย /api/v1
รูปแบบJSON (UTF-8) · เวลาเป็น ISO 8601 พร้อมเขตเวลา (+07:00)
SpecOpenAPI 3.0 (openapi.yaml) — นำเข้า Postman / Swagger UI ได้ทันที

การยืนยันตัวตน

ทุกคำขอต้องแนบ API Key ที่ผู้ดูแลระบบสร้างจากเมนู REST API ในระบบ เลือกแบบใดแบบหนึ่ง

X-API-Key: cdhl_live_xxxxxxxxxxxxxxxxxxxxxxxx
# หรือ
Authorization: Bearer cdhl_live_xxxxxxxxxxxxxxxxxxxxxxxx

คีย์แต่ละตัวกำหนดสิทธิ์ (scope) ได้ และยกเลิกสิทธิ์ได้ทันทีโดยไม่กระทบคีย์อื่น

Scopeอนุญาต
read:latest/latest, /points, /meta/last-update
read:history/history
read:status/devices/status
read:alarms/alarms
control/control, /sim/scenario (ผู้ปฏิบัติงานขึ้นไป)

จำกัดจำนวนการเรียก

กำหนดได้ต่อคีย์ (30 / 60 / 120 / 600 ครั้งต่อนาที) ทุกคำตอบมี header

X-RateLimit-Limit: 60

รูปแบบข้อมูล

ค่าตัวเลขเป็นหน่วยตามจุดตรวจวัด quality บอกคุณภาพข้อมูล: good ปกติ, bad_comm ขาดการสื่อสารกับอุปกรณ์, uncertain ค่าไม่แน่นอน

ตัวกลาง (Edge Gateway) — ข้อมูลกลายเป็น JSON ได้อย่างไร

อุปกรณ์ในตู้ควบคุมใช้โปรโตคอลอุตสาหกรรมคนละแบบ ระบบภายนอกต้องการ JSON ผ่าน HTTPS จึงมี CoreDash Edge Gateway เป็นตัวกลางในตู้ควบคุม

Inverter ACS580 ×2 ─┐
Power Meter M1M 20 ─┼─► PLC FX5U ──Modbus TCP──► Edge Gateway ──HTTPS + JSON──► Web App · มือถือ · ERP · BI
Flowmeter (RS-485) ─┘    (D-register)            อ่านทุก 1 วินาที
                                                 Alarm → LINE / Telegram / Email
                                                 ประวัติ + Audit log · AES-256-GCM
ขั้นทำอะไร
1. อ่านGateway อ่าน D-register ของ PLC ทุก 1 วินาทีตาม Register Map (เช่น D100–D101 = system.pressure แบบ float32)
2. แปลงคูณ scale ใส่หน่วย ตรวจคุณภาพข้อมูล แล้วเก็บเป็นจุดตรวจวัดชื่อเดียวกับ API
3. ให้บริการตอบคำขอ REST เป็น JSON ตรวจ API Key, scope, rate limit และเข้ารหัสเพิ่มได้
4. สั่งงานรับ POST /control ตรวจสิทธิ์และ Interlock แล้วเขียนกลับไปที่ PLC พร้อมบันทึก Audit log

ทำไมไม่ต่อ PLC ตรงกับ Cloud: PLC ส่ง HTTPS/JSON ไม่ได้ และการเปิด Modbus ออกอินเทอร์เน็ตเสี่ยงถูกสั่งงานจากภายนอก Gateway จึงเป็นจุดเดียวที่คุยกับ PLC และตรวจสิทธิ์ทุกคำสั่ง ถ้าอินเทอร์เน็ตหลุด Gateway ยังเก็บข้อมูลต่อ แล้วส่งย้อนหลังเมื่อกลับมา

เข้ารหัสข้อมูล (AES-256-GCM)

ทุกการเชื่อมต่อใช้ HTTPS อยู่แล้ว ถ้าระบบปลายทางต้องการเข้ารหัสตัวข้อมูลเพิ่ม ส่ง header นี้ (หรือผู้ดูแลกำหนดให้ API Key นั้นเข้ารหัสทุกครั้ง)

X-CD-Encrypt: aes-256-gcm

คำตอบจะเป็นซอง JSON แทนข้อมูลปกติ ถอดรหัสแล้วได้ JSON เดิมทุกประการ

{ "enc": "aes-256-gcm", "kid": "v1", "iv": "base64 12 byte", "tag": "base64 16 byte", "data": "base64" }
กุญแจ32 byte (CD_AES_KEY) สร้างด้วย node tools/keygen.js บน Gateway
IVสุ่มใหม่ 12 byte ทุกคำตอบ
ตรวจการแก้ไขtag 16 byte ในตัว (GCM) — ข้อมูลถูกแก้แม้ 1 bit ถอดรหัสจะล้มเหลว

วิธีใช้

  1. ผู้ดูแลระบบสร้างกุญแจด้วย node tools/keygen.js บน Gateway
  2. ส่งกุญแจให้ระบบปลายทางทางช่องทางปลอดภัย (ไม่ส่งทางอีเมล/แชท) และเปลี่ยนกุญแจทุก 90 วัน
  3. ระบบปลายทางเรียก API พร้อม X-CD-Encrypt: aes-256-gcm แล้วถอดรหัสตามตัวอย่าง
# Python (pip install requests cryptography)
import base64, json, requests
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
env = requests.get(URL + "/api/v1/latest", headers={"X-API-Key": KEY, "X-CD-Encrypt": "aes-256-gcm"}).json()
b = base64.b64decode
payload = json.loads(AESGCM(AES_KEY).decrypt(b(env["iv"]), b(env["data"]) + b(env["tag"]), None))
// Node.js
const b = (s) => Buffer.from(s, 'base64');
const d = crypto.createDecipheriv('aes-256-gcm', AES_KEY, b(env.iv)); d.setAuthTag(b(env.tag));
const payload = JSON.parse(Buffer.concat([d.update(b(env.data)), d.final()]));

{ "error": { "status": 429, "code": "RATE_LIMITED", "message": "เกินจำนวนการเรียกที่กำหนด 60 ครั้ง/นาที" } }
HTTPcodeสาเหตุแนวทางแก้
400INVALID_PARAMETERพารามิเตอร์ผิดรูปแบบตรวจ start/end/interval/agg
400RANGE_TOO_LARGEเกิน 10,000 จุดข้อมูลเพิ่ม interval หรือแบ่งช่วง
401UNAUTHORIZEDไม่ได้ส่ง API Keyแนบ X-API-Key
401INVALID_API_KEYคีย์ผิดหรือถูกยกเลิกขอคีย์ใหม่จากผู้ดูแลระบบ
403FORBIDDENคีย์ไม่มี scope ที่ต้องใช้ขอเพิ่ม scope
409INTERLOCKคำสั่งขัดกับ Interlock (เช่น E-Stop)แก้สาเหตุที่หน้างานก่อน
501ENCRYPTION_NOT_CONFIGUREDขอเข้ารหัสแต่ยังไม่ได้ตั้งกุญแจผู้ดูแลรัน tools/keygen.js
400ENCRYPTION_NOT_ALLOWEDขอวิธีเข้ารหัสอื่นที่ไม่ใช่ AES-256-GCMใช้ X-CD-Encrypt: aes-256-gcm
404POINT_NOT_FOUNDไม่พบจุดตรวจวัดดู GET /points
429RATE_LIMITEDเกินโควตาต่อนาทีรอตาม Retry-After
503DEVICE_OFFLINEอุปกรณ์ต้นทางขาดการสื่อสารลองใหม่ / ตรวจสถานะ
500INTERNAL_ERRORข้อผิดพลาดภายในแจ้งผู้ดูแลพร้อม X-Request-Id
